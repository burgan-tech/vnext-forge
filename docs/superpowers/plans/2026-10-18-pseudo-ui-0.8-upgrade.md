## Runtime facts the plan relies on (verified in `vnext/src/BBT.Workflow.Application/Instances/InstanceQueryAppService.cs`)

- While a sub-flow is active the **view** (`GetSubFlowViewWithOverrideAsync`) and the **master schema** endpoints forward to it; `data.href` is always built from the *parent* id (`BuildDataUrl(input.Domain, input.Workflow, instance.Id)`), so the parent's data 304s while the child's view is on screen.
- `activeCorrelations` = parent's own correlations **concatenated with** the sub-flow's (`mainFlowCorrelationHrefs.Concat(subFlowStateInfo.SubFlowActiveCorrelations)`), recursively. Only one SubFlow (`S`) can be open per instance (it blocks the parent), so the `S` entries that are not completed form the chain root→leaf in order: **the last open `S` entry is the leaf.** `P` (SubProcess) entries run beside the parent and never change the data target.
- Each correlation carries `subFlowDomain`, `subFlowName`, `subFlowInstanceId` — enough to call `quickrun/getData` for the child.
